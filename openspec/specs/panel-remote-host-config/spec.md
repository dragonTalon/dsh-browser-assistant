# panel-remote-host-config Specification

## Purpose

让扩展面板可以连接部署在本机之外的 dsh：用户在侧边栏的系统配置弹窗里填入 dsh host 与 token，保存前就能当场验证地址是否可达、token 是否被接受，从而在不改动桥接层的前提下支持家庭服务器、内网机器与反向代理域名等部署形态。

## Requirements

### Requirement: 系统配置入口与生效地址预览

面板的状态栏 SHALL 提供一个可点击的配置入口，点击后打开系统配置弹窗；弹窗 SHALL 提供 dsh host 输入、token 输入、测试连接、保存并重连、恢复本机自动发现五个交互，并同时提供关闭操作。host 输入变化时，面板 SHALL 立即显示该输入将解析成的生效地址，且此预览 MUST NOT 产生任何网络请求。

#### Scenario: 打开配置弹窗

- **WHEN** 用户在状态栏点击配置入口
- **THEN** 系统配置弹窗打开，并回填当前已持久化的 host 与 token（未配置时为空），生效地址预览同步显示当前解析结果

#### Scenario: 输入即预览且不触网

- **WHEN** 用户逐字输入 `10.0.0.7:3080`，桥连接处于已连接状态
- **THEN** 输入框下方实时显示生效地址，输入完成后为 `ws://10.0.0.7:3080/ext/bridge`，且整个过程没有发起任何 WebSocket 或 HTTP 请求

#### Scenario: 关闭弹窗不影响连接

- **WHEN** 弹窗打开期间用户点击关闭
- **THEN** 弹窗关闭，当前桥连接状态与地址保持关闭前的值不变

### Requirement: host 地址归一化

面板 SHALL 按以下规则把 host 输入解析为桥的 WebSocket 端点，并把解析结果作为连接目标：输入留空时 MUST 使用本机自动发现；输入不带 scheme 时 SHALL 补 `ws://` 与桥路径；输入带 scheme 时 SHALL 保留原 scheme，并在路径为空或为 `/` 时补桥路径；输入含非根路径时 SHALL 原样保留该路径。解析失败（无法构成合法 URL、端口越界、使用了 `ws`/`wss`/`http`/`https` 之外的 scheme）时面板 SHALL 判定为地址无效，MUST NOT 使用该地址发起任何连接。

#### Scenario: 补齐 scheme 与路径

- **WHEN** 用户输入 `10.0.0.7:3080` 并保存
- **THEN** 生效地址为 `ws://10.0.0.7:3080/ext/bridge`

#### Scenario: 保留显式 scheme 以支持 TLS 反代

- **WHEN** 用户输入 `wss://dsh.example.com`
- **THEN** 生效地址为 `wss://dsh.example.com/ext/bridge`

#### Scenario: 完整 WebSocket URL 原样使用

- **WHEN** 用户输入 `ws://10.0.0.7:3080/ext/bridge`
- **THEN** 生效地址与输入完全一致

#### Scenario: 输入留空回落本机自动发现

- **WHEN** 用户把 host 清空为空白并保存
- **THEN** 面板回到本机自动发现流程（探测本机候选端口并读取发现端点），生效地址预览显示为空

#### Scenario: 非法地址不发起连接

- **WHEN** 用户输入 `ftp://10.0.0.7:3080` 或 `10.0.0.7:99999` 并保存
- **THEN** 面板显示地址格式无效，且不发起任何 WebSocket 连接

### Requirement: token 归一化

面板 MUST 在保存与测试连接之前去除 token 输入首尾的空白字符，并把去除后的值用于握手与持久化。此要求用于消除用户按提示读取本机 token 文件时必然引入的尾部换行。

#### Scenario: 带尾部换行的 token 仍然可用

- **WHEN** 用户粘贴的 token 为 `a3f9…9c1\n`（末尾含换行），地址与 token 均正确
- **THEN** 面板以去除换行后的 token 发起握手，测试连接与保存后连接均成功

#### Scenario: 两侧都是空白视为未填写

- **WHEN** 用户只输入空格并保存
- **THEN** 面板把 token 视为空值，与未填写的行为一致

### Requirement: 配置现场的一次性验证

面板 SHALL 提供测试连接动作，对当前输入的地址与 token 发起一次完整握手（建立 WebSocket 连接并发送 `hello`，直至收到 `hello.ok` 或失败），并 MUST NOT 影响正在工作的桥连接：该动作 MUST 使用独立的临时连接，MUST NOT 复用或重启当前桥连接客户端。测试期间面板 SHALL 阻止重复触发同一动作。

#### Scenario: 有效配置验证通过

- **WHEN** 用户填入可达的地址与正确的 token 并点击测试连接
- **THEN** 面板显示验证通过，并展示握手协商结果（已连接的地址与快照预算）

#### Scenario: 验证不影响活跃连接

- **WHEN** 桥当前处于已连接状态，用户点击测试连接
- **THEN** 测试使用独立连接完成握手，当前桥连接保持已连接状态，不出现被替换而断开的现象

#### Scenario: 测试进行中不重复触发

- **WHEN** 用户点击测试连接后尚未返回结果，又再次点击
- **THEN** 面板不发起第二次测试，该动作在结果返回前保持不可重复触发

### Requirement: 分阶段的失败诊断

测试连接与连接失败时，面板 SHALL 区分并分别展示以下阶段：地址无效（归一化失败）、地址不可达（WebSocket 未能建立连接）、token 被拒绝（服务端以 `4002` 关闭）、握手超时（连接建立后在握手时限内未收到 `hello.ok`）。面板 MUST NOT 把上述阶段合并为同一条「连接失败」文案。

#### Scenario: 地址不可达

- **WHEN** 用户对 `10.0.0.7:3080` 点击测试连接，该地址没有监听服务
- **THEN** 面板提示地址不可达（或端口未开放），且不提示 token 相关的原因

#### Scenario: token 被拒绝

- **WHEN** 地址可达但 token 与服务端不一致，用户点击测试连接
- **THEN** 面板提示地址可达但 token 被拒绝，且不提示网络不可达

#### Scenario: 握手超时

- **WHEN** 连接已建立但对端在握手时限内未返回 `hello.ok`
- **THEN** 面板提示地址可达但握手超时

### Requirement: 保存、持久化与重连

保存配置时，面板 SHALL 先持久化 host 与 token，再以新配置重连桥。保存动作 MUST NOT 要求用户先通过测试连接。重连失败时配置弹窗 SHALL 保持打开并展示失败阶段，使用户可以直接修改后重试。host 非空时，连接判定 MUST NOT 回落到本机自动发现。

#### Scenario: 保存后立即重连

- **WHEN** 用户填入可达地址与正确 token 并点击保存并重连
- **THEN** 配置被持久化，桥以新地址重连成功，状态栏显示已连接，配置弹窗关闭

#### Scenario: 未测试也能直接保存

- **WHEN** 用户填入地址后未点击测试连接，直接点击保存并重连
- **THEN** 面板按归一化结果直接发起连接，不要求先完成测试

#### Scenario: 重连失败保留输入

- **WHEN** 用户保存了一个不可达地址
- **THEN** 配置弹窗保持打开、展示地址不可达的阶段提示，且已输入的 host 与 token 不被清空，本轮不建立任何桥连接

#### Scenario: 远端配置失败不回落本机

- **WHEN** host 已配置为 `10.0.0.7:3080`，该地址不可达，而本机 3080 端口有 dsh 在运行
- **THEN** 面板保持未连接状态并持续重试该远端地址，MUST NOT 连接本机 dsh

#### Scenario: 恢复本机自动发现

- **WHEN** 用户在已配置远端地址的情况下点击恢复本机自动发现
- **THEN** host 被清空，连接判定回到本机自动发现流程

### Requirement: 远端连接的功能缺口提示

当面板因特权方法被拒（`forbidden`）而收到 RPC 失败时，面板 SHALL 展示说明该操作仅在连接本机 dsh 时可用，MUST NOT 只呈现原始错误码或原始错误消息。

#### Scenario: 远端下调用特权方法

- **WHEN** 桥连接的是非回环地址，用户触发一个被服务端判定为回环专属的 RPC 并收到 `forbidden`
- **THEN** 面板提示该操作仅在本机连接下可用，并说明当前连接为远端

#### Scenario: 本机下不误报

- **WHEN** 桥连接的是本机 dsh，且一次 RPC 因其它原因失败
- **THEN** 面板不展示远端不支持相关的说明

### Requirement: 令牌与地址的持久化边界

面板 SHALL 只在本扩展的本地存储中持久化 host 与 token，MUST NOT 将其写入页面上下文、MUST NOT 通过桥发送给 dsh。连接建立后展示或上报的地址信息 MUST NOT 改变既有安全边界：页面数据仍为文本快照，特权方法对非回环来源仍一律拒绝，密码与卡号仍永不离开页面。

浏览器写操作的授权强度 SHALL 由会话权限档位决定（档位语义见 `browser-permission-tiers` 能力），连接远端 dsh 时该判定 MUST 与连接本机时一致，MUST NOT 因连接目标而放宽。档位求解 MUST 以所连 dsh 会话的权限投影为唯一真相源，扩展本地配置 MUST NOT 参与。

#### Scenario: 配置不外泄

- **WHEN** 用户保存了 host 与 token 并成功连接
- **THEN** 两者仅存在于扩展本地存储与桥握手中，页面上下文与普通 RPC 载荷中都不出现 token 值

#### Scenario: 放宽连接目标不削弱审批

- **WHEN** 桥连接的是远端 dsh，会话 S 的档位为 `workspace-write`，模型发起一个状态变更类工具调用
- **THEN** 面板仍弹出人工审批，行为与连接本机时一致

#### Scenario: 远端连接不改变档位判定来源

- **WHEN** 桥连接的是远端 dsh，扩展本地配置指示无需审批，而会话 S 的权限投影档位为 `read-only`
- **THEN** 该状态变更类调用被拒绝，MUST NOT 因扩展本地配置而放行
