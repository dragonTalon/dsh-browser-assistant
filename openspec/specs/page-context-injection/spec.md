# page-context-injection Specification

## Purpose

规定面板把活动标签页的「网页描述」注入模型 prompt 的时机:普通文本与技能消息仅在该会话首条消息注入一次,区域截图消息每轮注入。

## Requirements

### Requirement: 文本与技能消息的网页描述仅会话首条注入

面板 SHALL 按会话记录「是否已注入过网页描述」。普通文本消息与技能消息 SHALL 仅在所属会话尚未注入过网页描述时,在该消息内容最前方注入 `[网页描述]`,并把该会话标记为已注入;该会话后续的文本/技能消息 MUST NOT 再注入网页描述。

#### Scenario: 会话首条文本注入网页描述

- **WHEN** 用户在活动标签页(URL 与标题已知)上,向尚未注入过网页描述的会话 S 发送第一条文本消息
- **THEN** 该 prompt 的内容首块为 `[网页描述]：<标题> (<url>)`,且 S 被记为已注入

#### Scenario: 同会话后续文本不再注入

- **WHEN** 会话 S 已注入过网页描述,用户在同一会话再次发送文本消息(页面可能已变化)
- **THEN** 该 prompt 的内容块中不出现 `[网页描述]`,仅含用户消息本身

#### Scenario: 会话粒度隔离

- **WHEN** 会话 S1 已注入、S2 未注入,用户切换到 S2 并发送首条文本消息
- **THEN** S2 的首条文本注入 `[网页描述]`;再切回 S1 发送的文本不注入

#### Scenario: 技能共享首条门控

- **WHEN** 用户在尚未注入过网页描述的会话 S 上,以 `/<name>` 形式发送一条技能
- **THEN** 该技能 prompt 注入 `[网页描述]` 并把 S 记为已注入;S 的后续消息(文本或技能)不再注入

### Requirement: 区域截图每轮注入网页描述

区域截图 prompt SHALL 每轮注入 `[网页描述]`,且不受文本门控影响;其分段顺序 MUST 保持 `[网页描述] → [截图描述] → 截图 → [用户问题]`。

#### Scenario: 区域截图始终注入网页描述

- **WHEN** 用户在会话 S 发送区域截图 prompt(无论 S 是否已注入过网页描述)
- **THEN** 该 prompt 始终以 `[网页描述]` 开头,顺序为「网页描述 → 截图描述 → 截图 → 用户问题」

#### Scenario: 区域截图先行后的文本不再注入

- **WHEN** 会话 S 的首个动作是区域截图(已注入网页描述),随后用户发送第一条文本消息
- **THEN** 该文本消息不注入 `[网页描述]`(S 已被区域截图标记为已注入)
