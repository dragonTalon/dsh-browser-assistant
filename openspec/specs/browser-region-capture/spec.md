# browser-region-capture Specification

## Purpose

让用户在原页面上直接框选一块区域，系统自动把「选区截图 + 选区内 DOM 元素清单 + 用户意图」打包成一段 prompt 发给 agent，使模型既能看见区域像素、又能看见背后的元素结构，从而更准确地理解页面。

## Requirements

### Requirement: 框选模式的进入与取消

侧边栏面板 SHALL 提供一个进入「框选模式」的按钮；用户点击后，当前受控页面上 SHALL 出现一个覆盖全页、可拖拽的选区层，供用户框选一块矩形区域。用户在发送前 MUST 能够随时取消框选（例如按 Esc 或点击取消），取消后页面恢复原状且不产生任何发送。

#### Scenario: 进入框选模式

- **WHEN** 用户在侧边栏面板点击框选按钮，且当前存在受控 tab
- **THEN** 受控页面进入框选模式，出现可拖拽的选区层，光标变为十字样式

#### Scenario: 发送前取消框选

- **WHEN** 用户已进入框选模式但尚未确认发送
- **THEN** 用户按 Esc 或点击取消后，选区层消失，页面恢复原状，不产生任何截图、元素提取或发送

#### Scenario: 无受控 tab 时无法进入

- **WHEN** 当前不存在受控 tab
- **THEN** 框选按钮不可用或点击后给出明确提示，不进入框选模式

### Requirement: 选区截图的生成

用户完成框选后，系统 SHALL 生成一张只覆盖选区范围的截图，且截图 MUST 不包含选区之外的页面内容。截图 MUST 保留选区在视口内的真实像素，不得用 DOM 重绘或近似渲染替代。

#### Scenario: 框选完成生成选区截图

- **WHEN** 用户在页面上拖拽完成一个矩形选区
- **THEN** 系统生成一张与选区矩形对齐、仅覆盖该选区的截图

#### Scenario: 截图为真实视口像素

- **WHEN** 用户框选的是当前视口中可见的区域
- **THEN** 截图内容与该区域在屏幕上的真实渲染像素一致

### Requirement: 选区内 DOM 元素清单的提取

系统 SHALL 提取与选区相交的 DOM 元素，并为每个元素生成一行结构化描述。元素的入选 MUST 依据可判定的语义判据——元素具备 id、具备显式 role，或属于语义标签集合；系统 MUST NOT 仅因元素带有 class 而将其纳入清单。每个入选元素的描述 SHALL 包含标签与相对选区的坐标，并 MAY 包含 id、class、role/aria 与文本摘要；当元素自身无直接文本时，文本摘要 SHALL 省略，不得回退到整页文本或标签名作为摘要。文本类语义标签（如代码、预格式化文本、引用、定义列表等）SHALL 属于语义标签集合而被保留。元素数量 MUST 不超过一个配置上限，超出时按可判定的顺序截断。元素描述中的敏感字段（密码、卡号等）MUST 按既有隐私规则遮蔽，不得以明文进入清单。系统 MUST NOT 把自身注入的选区交互层节点（覆盖层、选框）纳入清单。

#### Scenario: 框选完成提取元素清单

- **WHEN** 用户在受控页面完成框选，选区内存在一个或多个符合语义判据的可见元素
- **THEN** 系统输出这些元素的结构化清单，每项含标签、相对坐标，并视元素自身情况附 id、class、role/aria 或文本摘要

#### Scenario: 纯 class 容器元素不入清单

- **WHEN** 选区内存在仅以 class 区分、无 id、无显式 role、且不属于语义标签集合的容器元素
- **THEN** 该元素不出现在清单中

#### Scenario: 容器元素无直接文本时省略摘要

- **WHEN** 一个入选元素自身没有直接文本（如仅包裹子元素的容器 div）
- **THEN** 该元素的描述只含标签、标识与相对坐标，文本摘要被省略，且不回退为整页文本或标签名

#### Scenario: 文本类语义标签被保留

- **WHEN** 选区内存在属于文本语义标签集合的元素（如代码、预格式化文本、引用、定义列表项）
- **THEN** 这些元素作为叶子被保留在清单中，并携带其自身文本摘要

#### Scenario: 元素数量超限截断

- **WHEN** 选区内符合语义判据的元素数量超过配置上限 N
- **THEN** 清单只保留 N 个元素，并按稳定的可判定顺序（如面积/文档顺序）截断

#### Scenario: 敏感字段遮蔽

- **WHEN** 选区内元素的文本包含密码或卡号等敏感字段
- **THEN** 元素清单中这些字段以遮蔽形式出现（如 `••••`），明文不进入清单

#### Scenario: 排除自注入选区节点

- **WHEN** 用户在受控页面完成框选
- **THEN** 系统注入的选区覆盖层与选框节点不出现在元素清单中

### Requirement: prompt 的自动打包与附件式呈现

系统 SHALL 把「用户意图 + 选区截图 + 选区内元素清单」自动打包成一段 prompt。框选完成后，系统 SHALL 把选区截图作为附件呈现在输入区（缩略图 + 可折叠元素清单 + 移除按钮），用户 MUST 在主输入框补充意图并统一发送；在用户发送前，系统 MUST NOT 发送任何截图像素或元素文本。

#### Scenario: 框选后呈现附件

- **WHEN** 用户框选完成
- **THEN** 输入区出现选区截图附件（缩略图 + 可折叠元素清单），主输入框获得焦点等待用户补意图

#### Scenario: 用户补意图并发送

- **WHEN** 用户在主输入框补充意图并点击发送
- **THEN** 系统把意图、选区截图与元素清单打包成 prompt，发送给 agent

#### Scenario: 空意图发送

- **WHEN** 用户未补充意图直接点击发送
- **THEN** 系统以「(未补充具体意图)」作为意图打包发送，不阻断

#### Scenario: 移除附件取消发送

- **WHEN** 用户点击附件的移除按钮
- **THEN** 系统丢弃本次框选产生的截图与元素清单，不发送任何内容

### Requirement: 区域截图 prompt 的分段结构

系统 SHALL 用统一的分段标签组装区域截图 prompt，分段顺序 MUST 为「[网页描述]（当前页面）→ [截图描述]（框选区域说明与选区内元素清单）→ 截图图片内容 → [用户问题]（用户意图）」。元素清单 MUST 保持在不可信内容包裹内。页面上下文标签 SHALL 与普通文本消息共用「[网页描述]」。

#### Scenario: 区域截图 prompt 的分段顺序

- **WHEN** 用户发送带截图的区域 prompt
- **THEN** 模型按「网页描述 → 截图描述 → 截图 → 用户问题」顺序收到内容，用户意图位于元素数据之后，元素清单仍在不可信内容包裹内

#### Scenario: 普通文本消息共用页面描述标签

- **WHEN** 用户发送普通文本消息
- **THEN** prompt 中的页面上下文使用「[网页描述]」标签，与区域截图保持一致

### Requirement: 图片内容向 agent 的投递

用户确认发送后，系统 SHALL 经现有会话通路把 prompt 发送给 agent。当选中模型支持图片输入时，prompt MUST 同时携带选区截图（作为图片内容）与元素清单文本；当选中模型不支持图片输入时，系统 MUST 剥离图片、仅发送元素清单与意图，并在面板给出「当前模型无视觉、已降级为元素描述」的提示。

#### Scenario: 视觉模型收到图片与元素

- **WHEN** 用户确认发送，且当前会话选中的模型声明支持图片输入
- **THEN** agent 收到含选区截图（图片内容）与选区内元素清单文本的 prompt

#### Scenario: 非视觉模型降级为元素清单

- **WHEN** 用户确认发送，且当前会话选中的模型不支持图片输入
- **THEN** agent 只收到元素清单与意图文本，不携带图片；面板提示已降级

### Requirement: 截图与元素文本的不可信内容边界

选区截图与选区内元素清单 SHALL 被视为不可信内容处理：元素清单文本 MUST 包裹不可信内容标记，防止被模型当作指令执行；截图作为用户选定的原始像素直接投递，MUST NOT 被页面内容替换或注入。

#### Scenario: 元素清单包裹不可信标记

- **WHEN** 元素清单被组装进 prompt
- **THEN** 清单文本以不可信内容标记包裹，模型渲染层将其视为数据而非指令
